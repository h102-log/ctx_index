# ctx_index

Claude Code에서 **컨텍스트 압축(compact) 이후에도 과거 턴의 존재와 원문 세부를 싼 비용으로 되찾을 수 있게** 하는 턴 색인 훅 `ctx-index` 프로젝트입니다.

> **현재 상태 — 설계 · 사전 검증 단계**
>
> 이벤트 스키마 확인, 구현 계획, lab 사전 시뮬레이션(①~③)을 마쳤습니다. 훅 본체 · 테스트 스위트 · 측정 스크립트(④)는 승인 대기 중이며, **이 저장소에는 아직 설치해서 쓸 수 있는 훅이 없습니다.** 근거와 미결정 사항은 [`docs/phase3-report.md`](docs/phase3-report.md)에 있습니다.

## 배경

긴 세션에서 컨텍스트 윈도우가 가득 차면 auto compact가 대화를 요약해 컨텍스트를 줄입니다.
이 요약 과정에서 아래와 같은 맥락이 누락되거나 흐려질 수 있습니다.

- 작업 목표와 현재 진행 상황
- 이미 내린 결정과 그 이유
- 작업 중인 파일, 지켜야 할 규칙·제약 사항

`ctx-index`는 요약을 더 잘 만드는 대신, **턴마다 요청과 답변 원문을 세션 밖 파일로 남기고 압축 직후에 그 목차만 컨텍스트에 넣습니다.** 목차는 요약이 아니라 "어떤 턴이 있었는지"의 목록이며, 세부가 필요하면 모델이 해당 턴 파일을 직접 읽습니다.

## 목표

- 압축 뒤에도 과거 턴이 **있었다는 사실**과 그 **원문**을 싼 비용으로 되찾을 수 있게 한다.
- 사용자나 모델의 개입 없이 **훅이 자동으로** 기록하고, 설정은 최소화한다.
- 평소에는 컨텍스트를 건드리지 않고 **압축 시점에만** 목차를 주입한다.

## 동작 방식

| 시점 | Hook | 역할 |
| --- | --- | --- |
| 요청 입력 | `UserPromptSubmit` | 새 턴을 열고 요청 전문을 턴 파일에 저장 |
| 응답 종료 | `Stop` | 최종 답변 원문을 같은 턴 파일에 덧붙임 |
| 압축 직후 | `SessionStart` (matcher: `compact`) | 턴 목차를 만들어 `additionalContext`로 주입 |

압축 직후 모델이 받는 목차는 아래와 같은 모양입니다. 프로토타입에 세 턴을 넣어 얻은 실제 출력이며(디렉터리 경로만 줄였습니다), 세부 형식은 승인 전이라 바뀔 수 있습니다.

```text
이 세션에서 있었던 턴의 목록입니다. 결과의 요약이 아니며 빠진 것이 있을 수 있습니다. 세부가 필요하면 아래 디렉터리의 해당 턴 파일을 직접 읽으세요.
디렉터리: <홈>/.claude/ctx-index/<session_id>/turns (턴 3개)
형식: 파일 크기 | 요청 → 답변
0001.md 12.6KB | [목표] 결제 모듈의 재시도 로직을 분석하고, 타임아웃이 중복 결제로 이어지는 경로가 있는지 확인해줘. 관련 파일은 paym… → 재시도 로직은 gateway 타임아웃(30초)과 클라이언트 타임아웃(10초)의 불일치 때문에 동일 주문에 대해 최대 3회까지 결제 요청을 중복 전송할 수 있습니…
0002.md 0.1KB | 테스트도 돌려줘 → 완료했습니다. 테스트 42개 모두 통과합니다.
0003.md 8.3KB | 지금까지 분석한 내용을 바탕으로 마이그레이션 계획을 단계별로 정리해줘. 다운타임 없이 진행해야 하고 롤백 절차도 반드시 포함… → 스키마 이중 기록(dual-write) 단계를 먼저 두고 2. 백필 3. 읽기 전환 4. 구 스키마 제거 순서로 진행하며 각 단계는 기능 플래그로 즉시 롤백할…
```

### 저장 구조

세션마다 디렉터리 하나를 씁니다. 경로는 세션 ID로만 정해지므로 브랜치 전환, 압축, `--resume`, `--continue`를 거쳐도 같은 곳에 쌓입니다(`/clear`와 `--fork-session`은 새 세션 ID를 받습니다).

```text
~/.claude/ctx-index/<session_id>/
├── turns/0001.md …     턴마다 파일 하나: 요청 전문 + 최종 답변 원문
├── meta.json           턴 번호, 시각, 상태(open/done), 요청/답변 미리보기, 원문 크기
├── compactions.jsonl   압축 시점의 마지막 턴 번호와 시각
├── errors.jsonl        훅 내부 예외 기록
└── index.md            마지막으로 주입한 목차의 스냅샷(디버깅용)
```

### 설계 원칙

- **모델은 쓰지 않습니다.** 모든 기록은 훅이 자동으로 수행합니다.
- **작업 중에는 아무것도 주입하지 않습니다.** 컨텍스트에 들어가는 것은 압축 시점의 목차뿐입니다.
- **원문은 무손실로 저장하고 목차만 주입합니다.** 주입문은 항상 6,000자 이하입니다.
- **훅은 작업을 막지 않습니다.** 어떤 예외가 나도 `errors.jsonl`에 남기고 exit 0으로 끝납니다.
- **표준 라이브러리만 씁니다.** 대상 환경은 Windows 11 · Python 3.12 · Claude Code 2.1.33x입니다.

전체 원칙과 완료 기준은 [보고서 0절](docs/phase3-report.md#0-과제-요약)에 있습니다.

## 시뮬레이션 실행

Python 표준 라이브러리만 있으면 됩니다. 설치할 의존성이 없습니다.

```bash
python3 lab/proto/sim_replay.py
```

```bash
python3 -u lab/proto/sim_fold.py
```

| 스크립트 | 검사 내용 | 소요 |
| --- | --- | --- |
| `sim_replay.py` | 실측 훅 페이로드를 프로토타입에 재생해 턴 귀속 · 기록 · 주입을 검사(37개 항목) | 1초 미만 |
| `sim_fold.py` | 합성 장기 세션으로 접기 단계와 6,000자 상한을 검사(무작위 3,000세션 포함) | 30초가량 |

두 스크립트 모두 실패가 있으면 0이 아닌 코드로 끝납니다. 실제 CLI로 페이로드를 다시 채집하는 방법은 [`lab/README.md`](lab/README.md)에 있습니다.

## 알려진 한계

- **Windows 실기 동작, 실제 모델 응답, 2.1.332 외의 버전은 아직 검증하지 못했습니다.** 검증은 Linux 컨테이너에서 실제 CLI를 로컬 모의 API로 구동해 수행했습니다.
- `/clear`와 `--fork-session` 이후에는 새 세션 ID가 발급되어 색인이 새로 시작됩니다. 이전 색인은 원래 디렉터리에 남습니다.
- 트랜스크립트 JSONL은 공식 문서에 없는 포맷이라 폴백 경로에서만 사용합니다.
