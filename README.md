# ctx_index

Claude Code에서 **컨텍스트 압축(compact) 이후에도 과거 턴의 존재와 원문 세부를 싼 비용으로 되찾을 수 있게** 하는 턴 색인 훅 `ctx-index` 프로젝트입니다.

> **현재 상태 — 구현 완료, Windows 실기 검증 대기**
>
> 훅 본체 · 테스트 스위트 · 측정 스크립트 · 설치 도우미(④)를 구현했고, Linux에서 테스트와 실제 CLI 종단 실행으로 확인했습니다. **대상 환경인 Windows 11에서의 동작은 아직 확인하지 못했습니다.** 설치하기 전에 아래 [Windows 확인 절차](#windows-확인-절차)를 따라 주세요. 검증 내용과 미검증 항목은 [`docs/phase4-report.md`](docs/phase4-report.md)에 있습니다.

## 배경

긴 세션에서 컨텍스트 윈도우가 가득 차면 auto compact가 대화를 요약해 컨텍스트를 줄입니다.
이 요약 과정에서 아래와 같은 맥락이 누락되거나 흐려질 수 있습니다.

- 작업 목표와 현재 진행 상황
- 이미 내린 결정과 그 이유
- 작업 중인 파일, 지켜야 할 규칙·제약 사항

`ctx-index`는 요약을 더 잘 만드는 대신, **턴마다 요청과 답변 원문을 세션 밖 파일로 남기고 압축 직후에 그 목차만 컨텍스트에 넣습니다.** 목차는 요약이 아니라 "어떤 턴이 있었는지"의 목록이며, 세부가 필요하면 모델이 해당 턴 파일을 직접 읽습니다.

## 목표

- 압축 뒤에도 과거 턴이 **있었다는 사실**과 그 **원문**을 싼 비용으로 되찾을 수 있게 한다.
- 사용자나 모델의 개입 없이 **훅이 자동으로** 기록하고, 설정은 최소화한다.
- 평소에는 컨텍스트를 건드리지 않고 **압축 시점에만** 목차를 주입한다.

## 동작 방식

| 시점 | Hook | 역할 |
| --- | --- | --- |
| 요청 입력 | `UserPromptSubmit` | 새 턴을 열고 요청 전문을 턴 파일에 저장 |
| 응답 종료 | `Stop` | 최종 답변 원문을 같은 턴 파일에 덧붙임 |
| 압축 직후 | `SessionStart` (matcher: `compact`) | 턴 목차를 만들어 `additionalContext`로 주입 |

압축 직후 모델이 받는 목차는 아래와 같은 모양입니다(훅에 세 턴을 넣어 얻은 실제 출력이며, 디렉터리 경로만 줄였습니다).

```text
이 세션에서 있었던 턴의 목록입니다. 결과의 요약이 아니며 빠진 것이 있을 수 있습니다. 세부가 필요하면 아래 디렉터리의 해당 턴 파일을 직접 읽으세요.
디렉터리: <홈>/.claude/ctx-index/<session_id>/turns (턴 3개)
형식: 파일 크기 | 요청 → 답변
0001.md 12.6KB | [목표] 결제 모듈의 재시도 로직을 분석하고, 타임아웃이 중복 결제로 이어지는 경로가 있는지 확인해줘. 관련 파일은 paym… → 재시도 로직은 gateway 타임아웃(30초)과 클라이언트 타임아웃(10초)의 불일치 때문에 동일 주문에 대해 최대 3회까지 결제 요청을 중복 전송할 수 있습니…
0002.md 0.1KB | 테스트도 돌려줘 → 완료했습니다. 테스트 42개 모두 통과합니다.
0003.md 8.3KB | 지금까지 분석한 내용을 바탕으로 마이그레이션 계획을 단계별로 정리해줘. 다운타임 없이 진행해야 하고 롤백 절차도 반드시 포함… → 스키마 이중 기록(dual-write) 단계를 먼저 두고 2. 백필 3. 읽기 전환 4. 구 스키마 제거 순서로 진행하며 각 단계는 기능 플래그로 즉시 롤백할…
```

목차는 항상 6,000자 이하입니다. 턴이 많아 넘칠 때만 단계적으로 접습니다: 직전 압축 이후 구간의 최신 턴부터 필요한 만큼 한 줄로 접기 → 미리보기 길이 절반 → 500바이트 미만의 작은 턴부터 접기 → 최신 쪽에서 과거로 더 접기. 접힌 구간도 파일은 그대로 있고 목차에 범위와 크기가 남습니다.

### 저장 구조

세션마다 디렉터리 하나를 씁니다. 경로는 세션 ID로만 정해지므로 브랜치 전환, 압축, `--resume`, `--continue`를 거쳐도 같은 곳에 쌓입니다(`/clear`와 `--fork-session`은 새 세션 ID를 받습니다).

```text
~/.claude/ctx-index/<session_id>/
├── turns/0001.md …     턴마다 파일 하나: 요청 전문 + 최종 답변 원문
├── meta.json           턴 번호, 시각, 상태(open/done), 요청/답변 미리보기, 원문 크기
├── compactions.jsonl   압축 시점의 마지막 턴 번호와 시각
├── index.md            마지막으로 주입한 목차의 스냅샷(디버깅용)
├── events.jsonl        훅 호출마다 한 줄인 진단 기록(프롬프트 · 답변 내용은 담지 않음)
└── errors.jsonl        훅 내부 예외 기록(예외가 있었을 때만 생김)
```

턴 파일은 아래처럼 생겼습니다. 작업 중에 추가로 입력한 요청과 이어진 답변은 같은 파일에 덧붙습니다.

```text
<!-- ctx-index | turn 0002 | session <session_id> | prompt <prompt_id> -->

## ◇ 요청 · 2026-11-26T12:30:35+09:00 · 22B

테스트도 돌려줘

## ◇ 답변 · 2026-11-26T12:30:41+09:00 · 59B

완료했습니다. 테스트 42개 모두 통과합니다.
```

### 설계 원칙

- **모델은 쓰지 않습니다.** 모든 기록은 훅이 자동으로 수행합니다.
- **작업 중에는 아무것도 주입하지 않습니다.** 컨텍스트에 들어가는 것은 압축 시점의 목차뿐입니다.
- **원문은 무손실로 저장하고 목차만 주입합니다.** 주입문은 항상 6,000자 이하입니다.
- **훅은 작업을 막지 않습니다.** 어떤 예외가 나도 `errors.jsonl`에 남기고 exit 0으로 끝납니다.
- **표준 라이브러리만 씁니다.** 대상 환경은 Windows 11 · Python 3.12 · Claude Code 2.1.33x입니다.

전체 원칙과 완료 기준은 [③ 보고서 0절](docs/phase3-report.md#0-과제-요약)에, 각 항목을 확인한 테스트는 [④ 보고서 3절](docs/phase4-report.md#3-명세-항목과-확인-방법)에 있습니다.

## 설치

필요한 것은 Python 3.8 이상(대상은 3.12)과 Claude Code 2.1.33x뿐입니다. 설치할 패키지는 없습니다. Windows에서 처음 설치한다면 먼저 [Windows 확인 절차](#windows-확인-절차)를 순서대로 따르세요.

저장소 루트에서 미리보기로 무엇이 바뀌는지 확인한 뒤 설치합니다(Windows에서는 `python3` 대신 `py -3.12`).

```bash
python3 tools/install_hook.py --dry-run
```

```bash
python3 tools/install_hook.py
```

설치 도우미가 하는 일은 다음과 같습니다.

- `hooks/ctx_index.py`를 `~/.claude/hooks/ctx_index.py`로 **복사**하고 그 복사본을 등록합니다. 저장소에서 브랜치를 바꾸거나 저장소를 옮겨도 실행 중인 세션의 훅이 바뀌거나 깨지지 않습니다. 훅을 고친 뒤에는 설치를 다시 실행하면 복사본이 갱신됩니다(`--in-place`를 주면 복사하지 않고 저장소의 파일을 그대로 등록합니다).
- `~/.claude/settings.json`의 `UserPromptSubmit`, `Stop`, `SessionStart`(matcher `compact`)에 훅을 **병합**합니다. 기존 훅과 다른 설정은 그대로 두고, 바꾸기 전에 `settings.json.bak-<시각>` 백업을 만듭니다. 다시 실행해도 중복 등록되지 않습니다.
- 인터프리터는 **설치를 실행한 Python의 절대 경로**로 등록합니다(`--python`으로 바꿀 수 있음). `python`이라는 이름만 등록하면 훅을 실행하는 쪽의 PATH에 따라 달라지고, Windows에서는 Microsoft Store 안내용 실행 파일이 잡힐 수 있기 때문입니다.
- 등록하기 전에 그 명령을 임시 디렉터리를 상대로 한 번 실행해 봅니다(`실행 점검`). 실패하면 `settings.json`을 바꾸지 않습니다.

등록되는 명령은 `python -I -c <실행기> <훅 경로>` 형태입니다. `python <훅 경로>`로 등록하면 훅 파일이 없어졌을 때 Python이 종료 코드 2로 끝나는데, Claude Code는 `UserPromptSubmit` 훅의 종료 코드 2를 "프롬프트 차단"으로 처리합니다. 실행기를 거치면 같은 상황이 일반 오류(종료 코드 1)가 되어 프롬프트는 그대로 처리되고 훅 오류만 표시됩니다(2.1.332에서 두 경우 모두 확인). `-I`는 작업 디렉터리의 `json.py` 같은 파일이 표준 라이브러리를 가리지 못하게 합니다.

새로 시작하는 Claude Code 세션부터 적용됩니다. 상태 확인과 제거는 다음과 같습니다.

```bash
python3 tools/install_hook.py --status
```

```bash
python3 tools/install_hook.py --uninstall
```

- 프로젝트 설정에만 등록하려면 `--settings <프로젝트>/.claude/settings.json`을 줍니다.
- 기본 형식(`--form exec`, 셸을 거치지 않는 `command` + `args`)이 동작하지 않는 컴퓨터에서는 `--form powershell` 또는 `--form bash`(Git Bash)로 다시 실행합니다. 두 형식은 대비용이며 Windows에서는 확인하지 못했습니다.
- 제거해도 복사해 둔 훅 파일과 `~/.claude/ctx-index`의 기록은 지우지 않습니다.

### 턴 파일 읽기 권한 (권장)

턴 파일은 프로젝트 디렉터리 밖에 있어서, 모델이 목차를 보고 턴 파일을 `Read`하려 하면 Claude Code가 권한을 묻습니다. 대화형에서는 그때 허용하면 되지만, 헤드리스(`-p`) 실행에서는 묻지 못해 거부됩니다(2.1.332에서 확인). 매번 묻지 않게 하려면 `~/.claude/settings.json`에 읽기 허용 규칙을 직접 추가합니다. Linux의 2.1.332에서는 이 규칙으로 프롬프트 없이 읽혔고, Windows에서는 확인하지 못했습니다.

```json
{
  "permissions": {
    "allow": ["Read(~/.claude/ctx-index/**)"]
  }
}
```

설치 도우미는 권한 설정을 건드리지 않습니다. 이미 `permissions.allow`가 있으면 배열에 한 줄만 더합니다.

## 사용

설치한 뒤에는 따로 할 일이 없습니다. 평소처럼 Claude Code를 쓰면 턴이 기록되고, 수동(`/compact`) · 자동 압축 직후에 목차가 한 번 주입됩니다.

- 기록 확인: `~/.claude/ctx-index/<세션 ID>/turns/`의 파일을 열어 봅니다. 마지막으로 주입한 목차는 같은 디렉터리의 `index.md`에 있습니다.
- 문제 확인: `errors.jsonl`이 생겼는지 봅니다(세션 디렉터리와 `~/.claude/ctx-index/` 바로 아래 두 곳). 훅은 오류가 나도 Claude Code를 막지 않습니다.
- 진단 기록 끄기: `events.jsonl`은 훅 호출마다 이벤트 이름 · 처리 결과 · 크기 · 처리 시간만 남깁니다. 끄려면 설치된 훅 파일의 `EVENT_LOG = True`를 `False`로 바꿉니다.
- 목차에 `(진행 중)`은 자동 압축 시점에 처리 중이던 턴, `(답변 없음/중단)`은 답변 없이 끝난 턴(Esc 중단 등), `(요청 미기록)`은 요청을 알 수 없는 턴입니다.
- 기록은 자동으로 지워지지 않습니다. 필요 없는 세션 디렉터리는 직접 지우면 됩니다. 턴 파일에는 프롬프트와 답변이 평문으로 들어 있습니다.

## 실사용 측정

1~2주 쓴 뒤, 모델이 실제로 턴 파일을 얼마나 찾아봤는지 셉니다.

```bash
python3 tools/ctx_index_measure.py --days 14
```

Windows에서 결과를 파일로 남길 때는 `>` 대신 `--out`을 씁니다(UTF-8로 저장).

```bash
python3 tools/ctx_index_measure.py --days 14 --out ctx-index-report.txt
```

- `~/.claude/projects` 아래 트랜스크립트의 **모든 도구 호출 입력**(Read, Grep, Glob, Bash, PowerShell, Agent, MCP 도구 등)에서 두 가지를 셉니다: ctx-index 아래 `turns/` 경로 참조, 그리고 `.claude/projects/` 아래 `.jsonl` 트랜스크립트 참조(목차 없이 원본 로그를 뒤지는 비싼 경로). 경로 구분자는 `/`와 `\`를 모두 인식하고, 도구 호출 1건을 1회로 셉니다. 권한이 거부된 호출도 모델이 참조하려 한 것이므로 셉니다.
- 서브에이전트 트랜스크립트도 세되 별도 열로 나누고 부모 세션에 귀속합니다(`--no-subagents`로 제외). 메인 모델이 조회를 서브에이전트에 맡겨도 색인을 쓴 것이기 때문입니다.
- 쓰기 도구(Write, Edit 등)가 기록하는 본문에만 경로가 나온 호출은 `Write(text)`처럼 따로 표시합니다. 문서를 고친 것이지 조회가 아닙니다.
- 뒤쪽 절반은 훅의 기록에서 나옵니다: 세션 · 턴 수, 압축과 주입 횟수, 접기 단계 분포, 오류 수, 훅 처리 시간. `압축(훅)`과 `압축(CLI)`이 다르면 훅이 압축을 놓친 것입니다.
- `--json`은 같은 내용을 JSON으로 냅니다. `--session <ID>`, `--since`, `--until`로 범위를 좁힙니다.

## Windows 확인 절차

구현과 검증은 Linux 컨테이너에서 했습니다. 아래는 Windows 11 PC에서 직접 실행해 확인할 명령과 확인 항목입니다. 명령은 저장소 루트에서 실행하고, PowerShell과 명령 프롬프트 어느 쪽이든 됩니다.

**1. 테스트 스위트** — 추가 설치 없이 표준 라이브러리만으로 돕니다(2~4분).

```bash
py -3.12 -m unittest discover -s tests
```

마지막 줄이 `OK (skipped=…)`이면 통과입니다. Windows에서는 POSIX 전용 검사 2개(권한 비트, 닫힌 표준 입출력)가 건너뛰어지고, Git Bash가 없으면 `bash` 형식 검사도 건너뜁니다. 실패가 있으면 출력 전체를 알려 주세요. 테스트는 임시 디렉터리만 쓰며 실제 `~/.claude`는 건드리지 않습니다.

**2. lab 시뮬레이션(선택)** — 프로토타입 기준 결과가 Windows에서도 같은지 봅니다.

```bash
py -3.12 lab/proto/sim_replay.py -q
```

```bash
py -3.12 -u lab/proto/sim_fold.py
```

**3. 훅 실행 시간** — 훅 1회 실행의 중앙값을 잽니다(Linux 기준 36~38ms).

```bash
py -3.12 tests/bench_hook.py
```

**4. 설치** — 미리보기에서 Python 경로와 훅 경로가 맞는지 본 뒤 설치합니다.

```bash
py -3.12 tools/install_hook.py --dry-run
```

```bash
py -3.12 tools/install_hook.py
```

`실행 점검: 통과`가 나와야 합니다. `실패`가 나오면 `settings.json`은 바뀌지 않은 상태이니, 출력 내용을 알려 주시고 `--form powershell`로 다시 시도해 보세요.

**5. 실제 세션에서 확인** — Claude Code를 새로 시작해 다음을 봅니다.

| 확인 항목 | 방법 | 기대 결과 |
| --- | --- | --- |
| 훅이 실행되는가 | 프롬프트 두세 개를 보낸 뒤 `%USERPROFILE%\.claude\ctx-index\<세션 ID>\turns\` 확인 | 턴마다 `0001.md`, `0002.md` …가 생기고 한글 · emoji가 깨지지 않음 |
| 평소에 아무것도 주입하지 않는가 | 대화 화면 | 훅 오류 표시나 훅이 넣은 문구가 없음 |

**6. 측정 스크립트** — 5번에서 모델이 턴 파일을 읽었다면 `턴 파일` 행에 1 이상이 나옵니다.

```bash
py -3.12 tools/ctx_index_measure.py --days 1
```

알려 주시면 좋은 것: 1 · 3 · 4 · 6번의 출력, 5번 표의 결과, 그리고 `errors.jsonl`이 생겼다면 그 내용입니다. 문제가 있어 되돌릴 때는 `py -3.12 tools/install_hook.py --uninstall`을 실행합니다.

## 알려진 한계

- **Windows 실기 동작, 실제 모델 응답, 2.1.332 외의 버전은 아직 검증하지 못했습니다.** 검증은 Linux 컨테이너에서 실제 CLI를 로컬 모의 API로 구동해 수행했습니다.
- 턴 파일은 프로젝트 디렉터리 밖에 있어, 읽기 허용 규칙이 없으면 모델이 읽을 때 권한 프롬프트가 뜹니다([턴 파일 읽기 권한](#턴-파일-읽기-권한-권장)).
- `/clear`와 `--fork-session` 이후에는 새 세션 ID가 발급되어 색인이 새로 시작됩니다. 이전 색인은 원래 디렉터리에 남습니다.
- 트랜스크립트 JSONL은 공식 문서에 없는 포맷이라 폴백 경로(답변이 페이로드에 없을 때, `UserPromptSubmit` 없이 시작된 턴의 요청 복원)에서만 사용합니다.
- 저장 경로 전체에 쓸 수 없으면 오류를 남길 곳도 없어, 훅은 조용히 exit 0으로 끝납니다.

전체 목록은 [④ 보고서 5절](docs/phase4-report.md#5-별도-표기-항목)에 있습니다.
