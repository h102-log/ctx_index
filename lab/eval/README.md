# lab/eval — autocompact 맥락 유지 A/B 실험

ctx-index가 **얼마나 쓸모 있는가**를 숫자로 재는 실험입니다. "훅이 동작하는가"는 `tests/`와 `lab/probe/`가 이미 확인했습니다. 여기서는 **autocompact 뒤에 압축 전 대화의 세부를 얼마나 되찾는지**를 훅이 없을 때와 있을 때 같은 조건으로 비교합니다.

> 상태: 실행기 · 채점기 · 분석기를 만들고 모의 API로 배선을 검증했습니다. 실제 모델 실행(파일럿, 본 실행)은 비용 승인 뒤에 합니다. 아래 "2.1.332에서 확인한 것"은 이 실험을 설계하면서 실측한 CLI 동작입니다.

## 무엇을 재는가

| 지표 | 정의 |
|---|---|
| **세부 회상 정답률** (핵심) | 압축 전에 심어 둔 세부를 압축 뒤 질문했을 때 정답을 말한 비율. 세부 질문(세션당 9개)만 셉니다 |
| 정답률 차이 B − A | 같은 대화 · 같은 질문을 짝지어 비교. 95% 구간은 세션(유닛) 단위 부트스트랩, 검정은 McNemar 정확 검정 |
| 오답 비율 | 틀린 값을 말하거나 지어낸 비율 (정답이 아니고 "찾을 수 없다"도 아닌 답) |
| 대조 질문 정답률 | 세션에 한 번도 나오지 않은 내용을 물었을 때 "기록에 없다"고 답한 비율 |
| 되찾는 비용 | 질문 1개당 비용 · 토큰 · 도구 호출 · 응답 시간, 정답 1개당 비용. 비용은 응답의 `usage`와 모델 단가로 계산하고 CLI의 누적 비용 차이로 교차 확인합니다 |
| 조회 경로 | 질문 중 턴 파일을 읽은 비율, 원본 트랜스크립트(`.jsonl`)를 뒤진 비율 (`tools/ctx_index_measure.py`와 같은 분류 규칙) |

질문 종류별(붙여넣기 속 값, 사용자가 말한 값, 제약, 모델이 찾아 준 값, 원문 인용, 결정 기준값, 순서)과 위치별(autocompact 발동 지점 대비 초반 · 중반 · 후반)로도 나눕니다.

## 조건

| | A: 훅 없음 (`report/baseline`) | B: ctx-index (`report/v1`) |
|---|---|---|
| 압축 전 대화 | 공유 빌드 그대로 (같은 세션) | 공유 빌드 그대로 (같은 세션) |
| 훅 | 등록 해제, 훅 파일과 `~/.claude/ctx-index` 기록 삭제 | 설치 도우미로 등록한 그대로 |
| 압축 직후 모델이 받는 것 | CLI 요약 + 원본 트랜스크립트 경로 안내 | CLI 요약 + 원본 트랜스크립트 경로 안내 + **ctx-index 목차** |
| 읽기 권한 | `Read(~/.claude/**)` — 트랜스크립트와 턴 파일 모두 | 같음 |

공통: Claude Code 2.1.332, 모델 `claude-opus-5-5`(CLI 기본 모델), effort는 CLI 기본값(`medium`), `CLAUDE_CODE_AUTO_COMPACT_WINDOW=400000`, 내장 도구는 `Read, Grep, Glob`만(부작용 없이 두 조건을 같게 두기 위해), 가짜 HOME · `env -i` 격리 실행(`run_cli_eval.sh`).

압축 직후 CLI는 훅이 없어도 "세부가 필요하면 전체 트랜스크립트를 읽으라"며 `.jsonl` 경로를 알려 줍니다. 그래서 이 비교는 "요약만"과 "목차"의 비교가 아니라 **원본 트랜스크립트를 뒤지는 기본 경로와 목차 · 턴 파일 경로의 비교**입니다. 정답률과 함께 되찾는 비용을 보는 이유입니다.

## 설계

한 유닛(세션 1개 × 반복 1회)은 네 단계입니다.

1. **공유 빌드** — ctx-index를 설치한 가짜 HOME에서 세션 하나를 만듭니다. 채움 턴(긴 로그 · 설정 · 코드 · 지표 붙여넣기와 짧은 분석 요청, 한 줄 대답)으로 컨텍스트를 채우다가, 대화가 각 세부의 목표 위치(발동 지점 350K 토큰 대비 0~88%)에 닿으면 그 세부를 심은 턴을 보냅니다. 330K 토큰에서 멈춥니다. ctx-index는 압축 전에는 컨텍스트에 아무것도 넣지 않으므로(불변식 2) 이 대화가 두 조건의 공통 압축 전 상태가 됩니다.
2. **분리** — HOME을 두 벌로 복사하고 A에서는 훅을 걷어 냅니다.
3. **autocompact** — 두 조건에서 같은 세션을 이어받아, 같은 "참고용 로그 — '확인'이라고만 답해 줘" 턴을 차례로 보냅니다. CLI가 스스로 autocompact하는 순간(`compact_boundary`, `trigger: auto`)을 기다립니다. 실행기는 발동 지점을 정하지 않습니다.
4. **질문** — 질문마다 압축된 세션을 따로 분기(`--resume <id> --fork-session`)해서 묻습니다. 질문끼리 서로의 조회 결과를 보지 못하고, 모든 질문이 같은 압축 직후 상태에서 시작합니다.

두 조건은 같은 대화를 압축하므로 짝지은 비교가 됩니다. 마무리 턴의 "확인" 답 한두 개만 다를 수 있습니다. 조건 실행 순서는 유닛마다 무작위입니다.

## 질문 세트와 채점

- 질문 세트: [`CASES.md`](CASES.md) — 세션 6개(결제 장애, 주문 DB 마이그레이션, 검색 지연, 인증 점검, 앱 크래시, 데이터 파이프라인), 세션마다 세부 질문 9개 + 대조 질문 2개. `gen_scenarios.py`가 시드로 생성하며 값은 모두 무작위라 기억으로 맞힐 수 없습니다. 생성기는 각 정답 값이 의도한 턴에 정확히 한 번만 있고 대조 질문의 낱말은 어디에도 없음을 스스로 확인합니다.
- 채점: [`grade.py`](grade.py) — 판정 모델 없는 프로그램 채점. 정답 값이 독립된 토큰으로 있으면 정답, 없고 "찾을 수 없다 / 모르겠다" 류이면 모름, 둘 다 아니면 오답. 원문 인용은 원래 요청이 90% 이상 순서대로 들어 있으면 정답. 후보를 둘 이상 늘어놓으면 정답이 아닙니다. 모름과 오답의 구분은 표현 패턴에 기댄 휴리스틱이라 실제 답을 직접 읽어 확인합니다(핵심 지표인 정답률은 이 구분과 무관합니다).
- `assistant_derived` 질문은 압축 전 그 턴에서 모델이 실제로 정답을 말한 경우에만 셉니다. 공유 빌드라 두 조건에서 똑같이 걸러집니다.

## 실행

모의 API로 배선 확인(비용 없음, 실제 CLI 사용):

```bash
python3 lab/eval/grade.py --selftest
```

```bash
python3 lab/eval/run_eval.py --api mock --mock-mode oracle --scenarios s01 --out lab/eval/.run/mock-oracle
```

`--mock-mode`는 `oracle`(두 조건 모두 11/11이어야 함), `null`(대조 질문 2개만 정답), `wrong`(0/11), `search`(도구로 조회한 뒤 정답 — A는 트랜스크립트, B는 턴 파일 조회가 집계되어야 함)입니다.

실제 모델(비용 발생, 승인 뒤에만):

```bash
python3 lab/eval/run_eval.py --api real --scenarios s01 --out lab/eval/.run/pilot --i-approve-paid-run
```

```bash
python3 lab/eval/analyze.py lab/eval/.run/pilot
```

- API 키는 `CTX_EVAL_API_KEY` 환경 변수에서 읽어 격리된 CLI에만 `ANTHROPIC_API_KEY`로 넘깁니다. 작업 중인 세션의 인증을 건드리지 않도록 `ANTHROPIC_API_KEY`라는 이름은 쓰지 않습니다. 클라우드 세션에서는 환경 설정의 환경 변수로만 넣을 수 있고(그 환경을 쓰는 모든 세션과 명령이 읽을 수 있으므로 사용 한도를 건 실험용 키를 쓰고 끝나면 지웁니다), 새 세션부터 적용됩니다. bash와 `env -i`를 쓰므로 Linux/macOS(Windows는 WSL) 전용입니다.
- 결과는 `--out` 아래 `report/{baseline,v1}/results.jsonl`(질문 1개에 한 줄), `traces/`(질문별 전체 대화), `units/<유닛>/unit.json`(빌드 · 압축 · 요약 세부)에 쌓입니다. 중단된 뒤 같은 명령을 다시 실행하면 이어서 합니다. `lab/eval/.run/`은 커밋하지 않습니다(모델 답과 트랜스크립트가 들어 있습니다).

## 2.1.332에서 확인한 것

모의 API에 실제 CLI를 붙여 확인했습니다(비용 없음). 근거 구분은 lab의 관례를 따릅니다.

| 사실 | 근거 |
|---|---|
| 모델을 지정하지 않으면 `claude-opus-5-5`를 요청하고, 압축 요약도 같은 모델로 만듭니다. 기본 요청 설정은 `effort: medium`, adaptive thinking, `max_tokens` 128,000 | [실측] 모의 API 요청 로그 |
| `auto` 압축 창에서는 보고된 사용량 900K 토큰까지 압축하지 않고 990K에서 압축합니다. 기본 설정의 실사용 autocompact는 거의 1M 토큰 시점입니다 | [실측] |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`(설정 `autoCompactWindow`)로 창을 바꿀 수 있고 최소값은 100,000입니다(50,000은 무시됨) | [바이너리] 설정 설명 문자열 · [실측] |
| 작은 대화에서는 100K 창이 60~70K, 200K 창이 160~170K, 400K 창이 349,550~349,950 토큰(직전 응답의 보고 사용량)에서 다음 프롬프트 때 압축합니다 | [실측] |
| 큰 대화(실제 붙여넣기로 330K+ 토큰)에서는 400K 창이라도 보고 사용량 350,190에서는 압축하지 않았고 363,644 이후에 압축했습니다. 디버그 로그(`--debug`)가 앞의 경우를 `autocompact: … level=warn effectiveWindow=380000`으로 남깁니다. CLI의 판단 기준은 API가 보고한 사용량과 정확히 같지 않으므로, 실행기는 발동 지점을 예측하지 않고 CLI가 압축하기를 기다립니다 | [실측] |
| 요약 프롬프트는 "모든 사용자 메시지 나열", "보안 · 제약 지시는 원문 그대로 보존"을 요구합니다. 짧은 사용자 지시는 훅 없이도 남을 가능성이 큽니다 | [실측] 압축 요청 본문 |
| 압축 직후 모델이 받는 메시지에 "세부가 필요하면 전체 트랜스크립트를 읽으라"는 안내와 `.jsonl` 경로가 들어갑니다(훅과 무관) | [실측] |
| `--resume <id> --fork-session`으로 압축된 세션을 분기하면 요약 · 트랜스크립트 안내 · ctx-index 목차가 그대로 이어집니다 | [실측] |
| 훅이 주입한 목차는 트랜스크립트에 `attachment.type == "hook_additional_context"`로 저장되고, 요청 전체 스냅숏(`api-request-blob`)에도 다시 들어갑니다. 트랜스크립트를 고쳐 목차만 빼는 방식은 쓰지 않았습니다 | [실측] |
| stream-json의 `total_cost_usd`는 세션 누적값이며 resume · fork를 거쳐도 이어집니다. 질문 1회의 비용은 차이로 구해야 합니다 | [실측] |
| 헤드리스 출력은 압축 때 `system` / `compact_boundary`(`trigger`, `pre_tokens`, `post_tokens`)를 냅니다 | [실측] |
| `Read(~/.claude/**)` 허용 규칙은 같은 경로에 대한 `Grep`도 권한 프롬프트 없이 통과시켰습니다 | [실측] |

## 한계

- 대상 환경(Windows 11)이 아니라 Linux 컨테이너에서 실행합니다. 모델 동작은 OS와 무관하지만 훅 지연 등은 따로 재야 합니다.
- 합성 시나리오입니다. 실제 사용에서는 컨텍스트 대부분이 도구 결과로 채워지고, 여기서는 붙여넣기로 채웁니다. 심은 세부는 디스크에 없는 대화 속 내용(붙여넣기, 사용자 발언, 모델의 결론)만 대상으로 합니다.
- 세션마다 압축은 한 번입니다. 같은 세션에서 여러 번 압축되는 경우는 재지 않습니다.
- 도구를 `Read, Grep, Glob`으로 제한했습니다. Bash나 서브에이전트로 찾는 경로는 두 조건 모두에서 막혀 있습니다.
- 모델 응답은 매번 달라집니다. 반복 수와 세션 수로 구간을 좁히며, 구간은 결과와 함께 적습니다.
