# ctx-index 훅 A/B 평가 (이 PC, 2026-11-27)

`ctx-index` 훅이 자동 압축 뒤에 압축 전 세부 내용을 다시 찾는 데 얼마나 도움이 되는지 쟀다. 같은 프롬프트를 두 폴더에서 `claude`로 실행해 비교한다. 저장소의 자동 실행기(`lab/eval/`)가 아니라 이 PC에서 새로 만든 절차와 프롬프트로 쟀다.

| 조건 | 폴더 | ctx-index 훅 |
|---|---|---|
| A | `runs\<실행>\A` | 꺼짐 (`"disableAllHooks": true`) |
| B | `runs\<실행>\B` | 켜짐 (실제 `~/.claude`에 등록된 훅 v1.0.0) |

## 결과 요약

압축된 세션에 "압축 전에 붙여 넣은 로그"의 세부를 묻는 질문 24개(대조 질문 2개 별도)를 던졌다. 수치는 세부 질문의 문항당 평균이다.

| 항목 | 압축 1회 (10쌍, 240문항) A / B | B가 줄인 비율 | 압축 3회 (11쌍, 264문항) A / B | B가 줄인 비율 |
|---|---|---|---|---|
| 정답 | 239 / 240, 240 / 240 | — | 264 / 264, 264 / 264 | — |
| 도구 호출 | 2.14 / 1.29 | 40% | 2.37 / 1.38 | 42% |
| 소요 시간(초) | 22.3 / 12.5 | 44% | 30.1 / 16.4 | 46% |
| 조정 비용(달러) | 0.1013 / 0.0662 | 35% | 0.1089 / 0.0683 | 37% |
| 환산 비용(달러) | 0.1561 / 0.1312 | 16% | 0.1546 / 0.1526 | 1% |

- **정답률은 두 조건이 같다.** 504문항 중 오답은 A의 1건뿐이다. 훅이 없어도 모델은 트랜스크립트 파일을 직접 검색해 답을 찾는다.
- **훅이 있으면 같은 답에 더 빨리, 더 적은 조회로 도달한다.** 도구 호출, 소요 시간, 조정 비용은 21쌍 모두에서 B가 적었다(실행 단위 부호 검정: 압축 1회 p=0.002, 압축 3회 p=0.001).
- **압축이 3번 나도 차이의 크기는 비슷하다.** 줄어드는 비율이 압축 1회와 3회에서 거의 같았다.
- **조회 경로가 갈린다.** A는 트랜스크립트(JSONL)를, B는 훅이 남긴 턴 파일을 읽었다.
- **환산 비용은 그대로 비교하면 안 된다.** 분기 세션의 첫 호출이 캐시에 새로 쓰는 양이 조회와 무관하게 달라서다. 이를 뺀 값이 조정 비용이다(아래 "비용 지표" 참고).

## 설계

### 조건

- 모델 `claude-opus-5-5`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW=400000`. 두 값은 폴더의 `.claude\settings.json`이 정한다(`new-run.ps1`이 만든다).
- 로그인, 전역 `CLAUDE.md`, 스킬, effort, 권한 설정은 이 PC의 실제 환경을 그대로 쓴다. 실제 `~/.claude\settings.json`은 건드리지 않는다.
- Claude Code 2.1.332.

### 절차

1. **채우기**: 로그 프롬프트(각 420줄, 약 5만 자, 약 2만 7천 토큰)를 p01부터 차례로 보낸다. 모델은 "확인"이라고만 답한다. 자동 압축이 정한 횟수만큼 나면 멈춘다.
2. **점검**: 압축이 자동이었는지, 질문 대상 로그(p01~p08)가 요약으로 넘어갔는지, A에 훅 기록이 없는지, B에 턴 파일(보낸 프롬프트 수만큼)과 목차 주입(압축 횟수만큼)이 있는지 확인한다.
3. **질문**: 질문마다 압축된 세션을 `--resume <세션ID> --fork-session`으로 분기해 하나씩 묻는다. 앞 질문의 조회 결과가 다음 질문에 섞이지 않는다. 분기 4개를 동시에 돌리고, 같은 질문의 A와 B는 같은 시점에 돈다.
4. **집계**: 분기 세션의 트랜스크립트에서 답, 도구 호출, 토큰 사용량, 시간을 뽑는다.

### 프롬프트와 질문

| 세트 | 내용 | 만드는 스크립트 |
|---|---|---|
| `prompts\s02` | 로그 프롬프트 16개(p01~p16)와 id·시각을 주고 묻는 질문 10개 | `prompts\make_set.py` |
| `prompts\s02k` | id·시각을 주지 않는 질문 26개. 최댓값 8, 순서 8, 건수 8, 대조 2 | `prompts\make_keyless.py` |
| `prompts\s03` | 압축 3회용 프롬프트 42개. p01~p16은 s02와 같은 파일, p17~p42는 같은 형식의 새 로그 | `prompts\make_long.py` |
| `prompts\s01` | r01에서 쓴 첫 세트. 비교에 쓰지 못했다(아래 "실행 기록") | — |

- 질문 대상은 항상 p01~p08이다. 압축 3회 실행에서는 이 로그들이 요약을 세 번 거친 뒤에 묻게 된다.
- 질문 예: "아까 붙여 준 결제 게이트웨이(pay-gw) 로그의 cache stats 줄 가운데 evictions 가 가장 컸던 줄의 시각과 그 값이 뭐였지?", "...로그에 ticket linked 줄이 모두 몇 건 있었지?"
- 대조 질문은 로그에 없는 것을 묻는다(정답 0건). 값을 지어내는지 본다.
- 질문 대상은 눈에 띄는 줄이 아니라 평범한 줄에서 계산한다. 특이한 줄은 압축 요약이 원문 그대로 옮기기 때문이다(r01에서 확인).
- 난수 시드가 고정이라 생성 스크립트를 다시 실행해도 같은 파일이 나온다.

### 지표

| 지표 | 정의 |
|---|---|
| 정답 | 정답표의 값이 답에 모두 들어 있으면 정답(`analyze.py`의 자동 판정). 대조 질문은 "없다" 또는 "0건"이면 정답 |
| 도구 호출 | 질문 하나에 답하면서 호출한 도구 수 |
| 소요 시간 | 질문 전송부터 마지막 응답까지(초) |
| 환산 비용 | 토큰 사용량 × `claude-opus-5-5` API 단가(입력 4, 출력 20, 캐시 읽기 0.20, 1시간 캐시 쓰기 8달러/100만 토큰). 실제 청구액이 아니라 구독 사용량을 달러로 바꾼 값이다 |
| 조정 비용 | 환산 비용에서 분기 세션 첫 호출의 캐시 쓰기를 뺀 값 |

- 요약에 답이 들어 있거나 조회 없이 답한 문항은 비교에서 뺀다(`analyze.py`). 집계한 21쌍에서는 해당 문항이 없었다.
- 통계는 실행(압축 세션 한 쌍)을 한 표본으로 본 부호 검정이 기준이다. 같은 실행의 문항들은 압축 요약을 공유해 서로 독립이 아니다.

### 비용 지표

분기 세션은 첫 호출에서 문맥의 끝부분을 캐시에 새로 쓴다. 이 양이 조회 행동과 무관하게 실행과 조건에 따라 달랐다.

| 첫 호출의 캐시 쓰기 (세부 질문 문항당 평균, 토큰) | A | B |
|---|---|---|
| 압축 1회 | 6,845 | 8,130 |
| 압축 3회 | 5,713 | 10,528 |

- 1만 토큰이면 환산 0.08달러로, 문항당 환산 비용의 절반쯤이다.
- 실행에 따라 A의 값이 거의 0이었다(m02에서 A 279, B 10,383토큰). 그런 실행에서는 환산 비용으로 B가 더 비싸게 나온다. A만 0에 가까웠던 이유는 확인하지 못했다.
- B의 문맥에는 훅의 목차가 더 들어 있다(턴 37개일 때 3,857자). 압축 3회에서 B의 값이 커진 것은 이 때문으로 추정한다.
- 이어지는 세션에서는 이 쓰기를 질문마다가 아니라 한 번만 낸다. 그래서 조회에 든 비용을 비교할 때는 조정 비용을 쓴다. 다만 목차가 문맥을 차지하는 것 자체는 훅의 실제 비용이다.

## 한계와 미검증

- **정답률은 상한이다.** 차이가 없다는 뜻이 아니라 이 난이도로는 볼 수 없다는 뜻이다. A도 트랜스크립트를 검색해 거의 다 맞혔다.
- **대화 내용이 한 종류다.** 21쌍 모두 같은 로그 프롬프트와 같은 26문항이다. 압축 요약이 달라지는 데 따른 변동은 반영됐지만, 다른 내용의 대화에서도 같은지는 재지 않았다.
- **도구 결과가 없는 대화다.** 프롬프트를 붙여 넣고 "확인"만 받는 구조라 트랜스크립트가 단순하다. 훅은 요청과 최종 답변만 저장하고 도구 결과는 저장하지 않으므로, 도구 결과에 든 세부를 묻는 경우는 재지 않았다.
- **대화형 세션은 한 쌍뿐이다.** r02만 사람이 붙여 넣었고 나머지는 `claude -p`로 채웠다. r02의 차이가 가장 작은 편이다(조정 비용 25%, 도구 호출 31% 감소).
- **자동 판정만 거친 실행이 있다.** r02~r07의 답 312개는 앞부분을 직접 읽어 자동 판정과 일치함을 확인했다. r08~r11과 m01~m11은 자동 판정만 거쳤다.
- **다른 모델, 다른 창 크기, 다른 Claude Code 버전에서는 재지 않았다.**
- **끝내지 못한 실행**: m12는 채우기를 마치고 질문 52개 중 42개만 받은 상태에서 멈췄다. 집계에 넣지 않았다. 계획했던 압축 3회 20쌍 중 11쌍만 집계했다.

|---|---|
| `new-run.ps1 <실행>` | `runs\<실행>\A`, `\B`와 프로젝트 설정을 만든다 |
| `fill.py <실행> [압축 횟수] [프롬프트 세트]` | 프롬프트를 보내 자동 압축까지 진행하고 점검 결과(`OK`/`PROBLEM`)를 출력한다. 세션 ID를 `runs\<실행>\sessions.json`에 적는다 |
| `ask.py <실행> <질문 세트>` | 질문마다 분기해 A·B에 묻는다. 답은 `out\<실행>-<세트>`에 저장한다 |
| `analyze.py <실행> [질문 세트]` | 분기 세션 기록을 집계해 `results-<실행>-<세트>.md`를 만든다 |
| `combine.py <질문 세트> [출력.md] <실행...>` | 여러 실행을 합쳐 실행별·실행 단위·종류별 표를 만든다 |
| `batch.py <질문 세트> [압축 횟수 프롬프트 세트] <실행...>` | 두 실행씩 채우고 한 실행씩 묻고 집계한다 |
| `usage.py [시작 시각]` | `claude -p "/usage"`로 구독 사용률을 읽어 `out\usage.log`에 기록한다 |
| `check.ps1 <실행>` | 실행의 세션별 훅 턴 수, 훅의 압축 기록 수, CLI의 압축 기록을 보여 준다 |
| `clip.ps1 <이름>` | 프롬프트나 질문 하나를 클립보드에 복사한다(수동 실행용) |

- `fill.py`, `ask.py`, `batch.py`는 끊기면 같은 명령으로 다시 실행한다. 끝난 단계와 받은 답은 건너뛴다. `fill.py`는 질문 단계를 시작한 뒤에는 다시 실행하지 않는다.
- `batch.py`는 주간 한도(모든 모델) 사용률이 90% 이상이면 새 실행을 시작하지 않는다(`STOP_AT`).
- 채우기를 마친 뒤 바로 질문 단계를 돌린다. 분기 세션은 원래 세션의 프롬프트 캐시(1시간 유지)를 읽으므로 간격이 길어지면 비용이 달라진다.
- 스크립트는 이 대화를 띄운 세션의 `CLAUDE*`·`ANTHROPIC*` 환경 변수를 빼고 `claude`를 실행한다.

### 수동 실행 (대화형)

1. 터미널 두 개에서 `cd C:\ctxeval\runs\<실행>\A; claude`와 `...\B; claude`를 실행한다.
2. `C:\ctxeval\clip.ps1 p01`로 프롬프트를 복사해 두 세션에 **붙여 넣어** 보낸다. 자동 압축이 날 때까지 번호 순서대로 반복한다.
3. `check.ps1 <실행>`로 확인한다. A는 `hook_turns`가 0, B는 보낸 프롬프트 수와 같아야 한다.
4. 두 세션을 닫고 `runs\<실행>\sessions.json`에 `{"A": "<세션ID>", "B": "<세션ID>"}`를 적는다. 그 뒤는 `ask.py`부터 자동 실행과 같다.

프롬프트는 파일 경로가 아니라 내용을 붙여 넣어야 한다. 경로를 보내면 모델이 파일을 Read로 읽는데, 훅은 도구 결과를 저장하지 않아 B의 턴 파일에 경로만 남고, 두 조건 모두 디스크의 파일을 다시 읽을 수 있어 비교가 되지 않는다.

## 실행 기록

| 실행 | 방식 | 압축 | 상태 |
|---|---|---|---|
| r01 | 대화형, 세트 s01 | 1회 (12번째 프롬프트) | 비교에 쓰지 못함 |
| r02 | 대화형, 세트 s02 | 1회 (13번째) | 집계. id·시각을 주는 질문 10개도 물었다(`results-r02.md`) |
| r03 | `claude -p` | 1회 (14번째) | 집계 |
| r04~r11 | `claude -p` | 1회 (13번째) | 집계 |
| m01~m11 | `claude -p`, 세트 s03 | 3회 (37번째, m09의 A는 39번째) | 집계 |
| m12 | `claude -p`, 세트 s03 | 3회 | 질문 42/52에서 중단, 집계 제외 |

- **r01이 무효인 이유**: 압축 뒤 문맥에 질문의 답이 두 조건 모두 남아 있었다. p03부터 파일 경로를 보내 B의 턴 파일에 경로만 저장됐고, 세트 s01에 심은 특이한 줄을 압축 요약이 원문 그대로 옮겼으며, 요약이 10번째 프롬프트 중간까지만 다뤄 그 뒤가 원문으로 남았다.
- **r02의 id·시각 질문**: 세부 질문 8개와 대조 질문 2개가 두 조건 모두 정답이었다. A는 트랜스크립트만(10회), B는 턴 파일만(8회) 읽었다.
- **압축 지점**: 압축 전 토큰은 실행마다 달랐고 약 36만 3천~38만 6천이다(r02 384,068, r03 384,875, r04~r11 약 36만 3천~36만 8천).
- **r07의 B**: 채우기가 한 번 끊겼다. p01에 "확인" 대신 한자("确认")로 답했고 `fill.py`가 그 답을 cp949 콘솔에 출력하다 멈췄다. 스크립트를 고친 뒤 같은 세션에 p02부터 이어서 보냈다. 질문 단계의 답은 모두 한국어였다.
- **m09**: A는 프롬프트 39개, B는 37개에서 세 번째 압축에 도달했다. 질문 대상은 두 세션 모두 요약 구간에 있다.

## 확인한 사실 (2026-11-27, Claude Code 2.1.332)

- 훅은 `UserPromptSubmit`에서 프롬프트 전체를 턴 파일에 저장하고(크기 제한 없음, 420줄 프롬프트가 약 48KB), `Stop`에서 최종 답변을 덧붙이며, `SessionStart[compact]`에서 목차를 주입한다. 도구 결과는 저장하지 않는다. 압축 전에는 문맥에 아무것도 더하지 않는다.
- 훅이 주입한 목차는 트랜스크립트에 `hook_additional_context`로 저장된다. 그래서 `--fork-session`으로 분기한 세션에도 목차가 따라간다.
- `claude -p "/context"` 출력이 A·B 모두 `claude-opus-5-5`, `/ 400k`였다. 프로젝트 설정이 없는 폴더는 `/ 450k`였다.
- 압축 요약은 미리 계산된다(`"precomputed": true`). 요약 시점 이후의 메시지는 원문으로 남는다. r02에서는 p11~p13이, `claude -p` 실행에서는 마지막 프롬프트 하나가 원문으로 남았다.
- 압축 요약은 실행마다 내용이 다르다. r02에서는 A의 요약에만 로그별 "최대 지연"이 적혀 있어, latency 최댓값을 묻는 질문은 세트 s02k에서 뺐다.
- 대화형 세션의 시작 사용량은 약 5만 3천 토큰, `claude -p`는 29,618토큰이었다.
- `claude -p --output-format json`의 `total_cost_usd`는 resume·fork를 거치며 누적된 값이라 쓰지 않았다. 비용은 트랜스크립트의 메시지별 사용량에서 계산한다.
- `claude -p "/usage"`로 구독 사용률을 명령줄에서 읽을 수 있다.

## 사용량

## 주의

- 실험 세션의 트랜스크립트(`~/.claude\projects\C--ctxeval-runs-*`)와 턴 파일(`~/.claude\ctx-index\<세션ID>`)은 실제 `~/.claude`에 남는다. 실사용 측정(`ctx_index_measure.py`)은 실험 시작 전까지만 보도록 `--until 2026-11-27T10:07:00`을 준다.
- 원본 답(`out\`), 실행 폴더(`runs\`), 문항별 답이 든 `results-*.md`는 저장소에 커밋하지 않는다. 모델 답에 금지 표현이 섞일 수 있다.
- `runs\wiring`은 배선 확인과 `/usage` 읽기에 쓰는 폴더다.
